Halfway through building **Tesseract**, my local-first Markdown editor, I hit a problem while drafting a short story between coding sessions.

I pasted a 3,000-word chapter into an AI assistant and asked whether the scene worked. It replied:

> "The scene has good pacing overall. The dialogue feels natural and the setting is vivid. Consider adding more sensory details and tightening the ending."

That response skimmed the chapter and handed out adjectives instead of a real critique.

---

## Missing Schemas, Vague Output

AI models struggle with fiction critique because open-ended prompts force them to improvise. Without explicit schemas and output formats, they default to safe praise.

Reading a writer's mood in Tesseract accomplishes little if the editorial feedback stays vague. I paused Tesseract for a week and built **The Manuscript**, a developmental editing skill for AI agents designed to diagnose drafts with structured rules.

---

## Seven Sub-Skills

The Manuscript splits the editing workflow into seven reference files covering first drafts through agent submission. Each file defines exact schemas and output formats so the agent follows a repeatable checklist.

### Continuity Tracker

Maintains a story bible covering characters, locations, objects, timelines, relationships, and open plot threads. Adding a chapter triggers checks against established canon.

> **Example output:** `⚠️ CONTRADICTION: Dr. Patel. Chapter 2 left her age unspecified; this chapter states she is 42. Confirm canon.`

### Character Voice

Profiles each character's vocabulary tier, sentence rhythm, verbal habits, emotional register, and blind spots, then audits new dialogue at the line level.

Instead of saying "this dialogue feels off," it outputs:

> **⚠️ VOICE DRIFT:** *"My lord Duke, with great respect, I've been analyzing our strategic position in considerable depth..."*
> Issue: Kael speaks in short, blunt sentences. This 40-word subordinate clause reads like Lord Ashford.

### Scene Diagnostics

Audits scenes across six dimensions: scene function, pacing, tension, POV consistency, showing vs. telling, and scene entry/exit. Standards adjust by genre so a slow literary scene faces different criteria than a thriller scene. Each finding cites exact lines and picks one priority fix.

### Plot Structure

Maps a manuscript against structural models (Three-Act, Save the Cat, Hero's Journey, Mystery Structure, Freytag's Pyramid, and Dan Harmon's Story Circle). The output locates where each beat lands or drops out, ordered by impact.

### Prose Style Guide

Extracts your prose profile from writing samples: sentence architecture, vocabulary register, interiority, description density, and tonal habits. The agent uses that profile to flag style drift or draft placeholder scenes in your voice.

### World-Building Codex

Tracks magic systems, geography, politics, history, culture, religion, and economy for fantasy and sci-fi manuscripts. Once you record a rule in the codex, the agent flags any chapter that breaks it.

### Query Letter Writer

Follows strict publishing conventions for query letters: hook (character, goal, obstacle, stakes), third-person present-tense story summary, metadata line, and bio. It bans rhetorical questions, theme statements, and cliffhanger teasers.

## Three-Step Workflow

1. **Route:** Match the writer's request to the right sub-skill.
2. **Load:** Read that sub-skill's reference file before writing a response.
3. **Execute:** Fill out the defined schema and output format.

> **Core rule:** The agent reads the sub-skill file before replying so schemas come from the reference docs rather than guesswork.

### Universal Rules

Five rules apply across all seven sub-skills:

- **Do not invent facts** about the story.
- **Surface contradictions without resolving them:** let the writer pick canon.
- **Keep one source of truth** inside defined schemas.
- **Separate stated facts from inferences** so writers can verify assumptions.
- **Act as an editor, not a co-author:** diagnose first, rewrite on request.

---

## Adapting to Experience Level

**Newer writers** receive short craft explanations before the critique runs. If the agent flags head-hopping, it explains what head-hopping is and why it breaks POV.

**Experienced writers** get straight diagnostics without preamble. If you already use craft terms, the agent skips definitions and points straight to the missing midpoint reversal.

---

## Line-Level Specificity

Generic tools say "the pacing could be tighter." The Manuscript says "paragraphs 4 to 7 describe the weather and making coffee before stakes appear; start the scene at the argument."

Generic tools say "check world-building consistency." The Manuscript says "Chapter 3 states magic requires touch, while Chapter 8 shows a mage drawing power across a room; pick which rule stands."

Each note cites exact lines, gives one priority fix per scene, and leaves final canon decisions to the author.

## Repository Structure

```
the-manuscript/
├── SKILL.md                    # Main skill with routing logic
└── references/
    ├── character-voice.md
    ├── continuity-tracker.md
    ├── plot-structure.md
    ├── prose-style.md
    ├── query-letter.md
    ├── scene-diagnostics.md
    └── worldbuilding-codex.md
```

`SKILL.md` handles routing and universal rules, while each file in `references/` holds the schema, checklist, and output template for one sub-skill. Loading files on demand keeps context lean.
