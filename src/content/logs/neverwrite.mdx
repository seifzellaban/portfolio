[NeverWrite](https://github.com/jsgrrchg/NeverWrite) is an Electron note-taking app built around an agent layer, similar to Obsidian. I found it in [a thread on r/ZedEditor](https://www.reddit.com/r/ZedEditor/comments/1t3nbgi/agentic_multipane_markdown_editor_inspired_by_zed/?utm_source=share&utm_medium=web3x&utm_name=web3xcss&utm_term=1&utm_content=share_button).

I run Fedora, and the releases page had an empty Linux row. Issue [#19](https://github.com/jsgrrchg/NeverWrite/issues/19) had sat open with no assignee, and the CONTRIBUTING guide listed Linux as a wanted target.

I picked up the issue, built the packaging pipeline, and landed my first merged open source PR.

---

## The Problem

NeverWrite ships a compiled Rust sidecar that the Electron main process forks at runtime. Adding Linux support took five pieces:

- `electron-builder` needed AppImage targets for `x64` and `arm64`
- Rust sidecar staging scripts needed cross-compilation for both Linux targets
- CI needed to build on `ubuntu-22.04` so binaries link against GLIBC 2.35 rather than a newer runner version that breaks on older distros
- `electron-updater` needed a `latest-linux.yml` feed for in-app updates
- The frameless titlebar built for macOS exposed a native menu bar on Linux and needed platform-aware window chrome

---

## Changes Made

I added Linux AppImage targets to the `electron-builder` config:

```json
"linux": {
  "target": [
    { "target": "AppImage", "arch": ["x64", "arm64"] }
  ],
  "icon": "build/icons/icon.png",
  "category": "Utility"
}
```

The staging scripts handled macOS and Windows sidecars. I extended them to cross-compile the Rust binary for Linux `x64` and `arm64` ahead of the Electron build so the bundler picks up each binary.

In CI, I pinned the Linux job to Ubuntu 22.04:

```yaml
runs-on: ubuntu-22.04
```

`ubuntu-latest` pointed to 24.04 with a GLIBC 2.38 baseline. Pinning to 22.04 keeps the baseline at GLIBC 2.35 so the AppImage launches across most current Linux installs.

For window chrome, I hid the native menu bar outside macOS in the main process:

```ts
if (process.platform !== 'darwin') {
  win.setMenuBarVisibility(false)
}
```

I added a CSS class on the drag region to handle compositing differences between macOS and GTK.

---

## Review and Merge

The maintainer ([@jsgrrchg](https://github.com/jsgrrchg)) reviewed the PR and pushed follow-up fixes to finish the updater feed config and bind the AppImage icon. We went back and forth over a day across seven commits touching the builder config, staging scripts, CI workflow, main process setup, and titlebar CSS. He squashed and merged it on May 9th.

---

## v0.2.5 Release

Version 0.2.5 shipped with Linux builds in the installer table:

| Platform | Architecture | Asset |
|----------|--------------|-------|
| Linux | x64 | `NeverWrite-0.2.5-x64.AppImage` |
| Linux | ARM64 | `NeverWrite-0.2.5-arm64.AppImage` |

In-app updates work on both architectures, the window chrome renders clean, and both Cmd+W and its Linux shortcut pass tests.
